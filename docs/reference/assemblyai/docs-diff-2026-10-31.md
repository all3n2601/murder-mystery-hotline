# AssemblyAI docs diff: snapshot (2026-10-17/18) vs live (2026-10-31)

Compared every local file in this folder against the live Markdown pages (`<docs URL>.md`) on 2026-10-31. Cosmetic changes (MDX → `> [!NOTE]`, relative → absolute links) were normalized out before comparing.

## Summary (read first)

1. **Streaming TTS is now officially documented and launched, and the documented protocol breaks our TTS adapter.** AssemblyAI-TTS-1 launched 2026-10-27 ([models reference](https://www.assemblyai.com/llms/models.md)), and a full "Text to Speech" section is now in the docs index ([llms.txt](https://www.assemblyai.com/docs/llms.txt)). The changes that affect `apps/server/src/adapters/tts.ts`, `packages/engine/src/voices.ts`, `cases/night-operator/case.json` and `tts-protocol.md`:
   - **The `voice` query param is retired.** Sending it with any value is refused with `3006` / `invalid_parameter` / `param: voice`. Use `voice_id`, with slugs like `aai-jane`, `aai-george` and so on ([voices](https://www.assemblyai.com/docs/tts/voices.md), [connect parameters](https://www.assemblyai.com/docs/tts/connect-parameters.md)). `tts.ts:89` sends `voice=`.
   - **The documented hosts are `wss://tts.us.assemblyai.com/v1/ws` and `wss://tts.eu.assemblyai.com/v1/ws`**, and there's "no global endpoint yet" ([endpoints](https://www.assemblyai.com/docs/tts/endpoints-and-data-zones.md)). Our `TTS_URL` (`wss://streaming-tts.assemblyai.com/v1/ws`, `tts.ts:11`) appears nowhere in the docs. I couldn't verify whether it still works.
   - **There's now a 120 s idle timeout** (close `3006`, `error_type: inactivity_timeout`). `KeepAlive` resets it, and `inactivity_timeout` can shorten it to 5–120 s ([connect parameters](https://www.assemblyai.com/docs/tts/connect-parameters.md#inactivity-timeout)). Our notes and the `tts.ts:9` comment say "an idle session never times out", which is wrong now. Per-voice lines that sit idle for more than 2 min during a call will be closed.
   - **The built-in voices are now 11:** `aai-jane` (default), `aai-alba`, `aai-anna`, `aai-charles`, `aai-eve`, `aai-george`, `aai-jean`, `aai-mary`, `aai-michael`, `aai-paul`, `aai-vera`. A catalog of thousands more `aai-*` voices sits on top ([voices](https://www.assemblyai.com/docs/tts/voices.md#built-in-voices)). `iris` and `reid` from our `voices.ts` aren't listed. The case uses anna, george, vera, michael and jean, which all have `aai-` equivalents.
   - **The limits are documented differently from what our probe found.** There's no documented concurrent-session cap ("sessions open at once are not counted"). The limit is on new sessions per minute: 5 on the free plan, 100+ on paid, counted separately from STT. `3009` now means `rate_limited`, with `retry_after_seconds` (1–60) and `retryable: true` ([limits](https://www.assemblyai.com/docs/tts/limits.md), [error handling](https://www.assemblyai.com/docs/tts/error-handling.md)). The memory note "3 concurrent" may be stale. The per-minute rule still argues for reusing sockets.
2. **The Voice Agent API is being retired.** It's described as "Being retired — don't recommend for new builds" and it "does not run AssemblyAI-TTS-1" ([models reference](https://www.assemblyai.com/llms/models.md)). All `voice-agents/voice-agent-api/*` pages have been removed from llms.txt, though they still load with unchanged content. This project doesn't use it.
3. **LLM Gateway: `qwen3.5-4b-32k-fast` hasn't changed.** It has the same params (`max_tokens`, `temperature`, `stream`), the same 32768 context, the same pricing ($0.1 / $0.5 per 1M), and no retirement date. The docs now use it as the example model ([available models](https://www.assemblyai.com/docs/llm-gateway/available-models.md), [create chat completion](https://www.assemblyai.com/docs/llm-gateway/api-reference/create-chat-completion.md)). `model` is no longer strictly required, because a new `aai_prompt` (saved prompts) can supply it. That doesn't affect `llm.ts`.
4. **Streaming STT v3: no substantive change.** The default is still `universal-3-6-pro`, with the same params and messages ([streaming websocket](https://www.assemblyai.com/docs/streaming/api-spec/streaming-websocket.md)).

## 1. Streaming STT v3 (`streaming_api-spec_streaming-websocket.md`)

- **Changed:** cosmetic only. The data-residency wording went from "never leaves the US/EU" to "is processed in the US/EU" ([source](https://www.assemblyai.com/docs/streaming/api-spec/streaming-websocket.md)).
- **No change:** the default `speech_model` is still `universal-3-6-pro`, and endpoints, query params, message types and turn-detection params are the same ([source](https://www.assemblyai.com/docs/streaming/api-spec/streaming-websocket.md), [model selection](https://www.assemblyai.com/docs/streaming/select-the-speech-model.md)).
- **Context (not in the local snapshot):** the free plan gets 5 new sessions/min and paid gets 100+ with auto-scaling. Exceeding the limit sends `Error` "Unauthorized Connection: Too many concurrent sessions" and closes with `1008`. Open sessions don't count, and un-terminated sessions auto-close after 3 h and are billed ([rate limits](https://www.assemblyai.com/docs/streaming/rate-limits.md)).

## 2. LLM Gateway

**Added**
- New models: `deepseek-v4.1-flash-1017`, `mercury-3`, `mercury-voice` (Inception Labs), `gpt-6.1-terra`, `beam-1.0` ([available models](https://www.assemblyai.com/docs/llm-gateway/available-models.md)).
- New saved prompts feature, with create/get/update/delete endpoints and the request fields `aai_prompt` and `prompt_replacements` ([saved prompts](https://www.assemblyai.com/docs/llm-gateway/saved-prompts.md), [create chat completion](https://www.assemblyai.com/docs/llm-gateway/api-reference/create-chat-completion.md)).

**Changed**
- `model` was dropped from `required` and is now "Required unless `aai_prompt` is set" ([create chat completion](https://www.assemblyai.com/docs/llm-gateway/api-reference/create-chat-completion.md)).

**Removed**
- No models were removed, and no new retirement dates were added. The existing ones are unchanged: `gemini-3.1-flash-lite` on 2027-05-07 and `gpt-4.1` on 2027-01-14 ([available models](https://www.assemblyai.com/docs/llm-gateway/available-models.md)).

**Rate limits** (no local snapshot to compare against; current content from [rate limits](https://www.assemblyai.com/docs/llm-gateway/rate-limits.md)):
- RPM and TPM are tracked per account × model × provider × region, over a sliding 60 s window. New accounts start at Tier 0 with 30 RPM; Tier 1 (any spend) gets 100 RPM.
- `max_tokens` is reserved against TPM while a request runs, and 8000 is reserved if it's unset. `llm.ts` defaults to 200, which is fine.
- A `429` carries `Retry-After` and `X-RateLimit-*` headers.

## 3. Streaming TTS (`tts-protocol.md`, `tts-markup.md`, `tts-voice-agent-voices.md`)

The local notes say this was undocumented. **It's now fully documented.** That covers 30 new pages under `/docs/tts/` plus the spec `https://www.assemblyai.com/docs/api-reference/specs/streaming-tts.yaml` ([llms.txt](https://www.assemblyai.com/docs/llms.txt)).

**Added (connection and auth)** ([connect parameters](https://www.assemblyai.com/docs/tts/connect-parameters.md))
- Hosts are `tts.us.assemblyai.com` and `tts.eu.assemblyai.com`, both on `/v1/ws`. US runs in us-east-1 and EU in eu-north-1 ([endpoints](https://www.assemblyai.com/docs/tts/endpoints-and-data-zones.md)).
- The `Authorization` header takes either the raw key or `Bearer <key>`. Browsers can pass a `token` query param instead.
- Temporary tokens come from `GET https://token.us.assemblyai.com/v1/token?product=tts&expires_in_seconds=…`, with an optional `max_session_duration_seconds` ([temp token](https://www.assemblyai.com/docs/tts/authenticate-with-a-temporary-token.md)).
- A bad credential still opens the socket and then sends `Error` `1008`.
- The connect params are `voice_id`, `model_id` (e.g. `assemblyai-tts-1`), `language` (full name such as `english`), `sample_rate` (8000/16000/22050/24000/44100/48000), `encoding` (`pcm_s16le`/`pcm_mulaw`/`pcm_alaw`), `word_boundaries`, `inactivity_timeout`, `extend_biometric_consent` and `token`.
- A duplicated param gets `3006`. Unknown params are echoed in `Begin.configuration.unknown_params`.
- `Begin.configuration` now also carries `model`, `session_ttl_sec`, a `limits` object and `resolved_voice` ([message frames](https://www.assemblyai.com/docs/tts/message-frames.md)).
- The docs state there's no speed, pitch, emotion or style param on the WebSocket, and no SSML or pronunciation dictionary on either API ([connect parameters](https://www.assemblyai.com/docs/tts/connect-parameters.md#parameters-that-do-not-exist)).

**Changed vs our probe notes** ([message frames](https://www.assemblyai.com/docs/tts/message-frames.md), [limits](https://www.assemblyai.com/docs/tts/limits.md))
- Valid client frames are `Generate`, `Flush`, `Cancel`, `KeepAlive` and `Terminate`. **`VoiceReference` is no longer listed**: cloning is now done in the dashboard and used through `voice_id` ([cloned voices](https://www.assemblyai.com/docs/tts/cloned-voices.md)).
- "No audio until `Flush`" only holds for short text. Once enough complete sentences are buffered, the server starts speaking before `Flush`. The docs recommend a `Flush` per sentence when streaming from an LLM.
- Text from consecutive `Generate` frames is joined with no separator.
- `Audio` frames now carry `flush_id`.
- After a `Cancel`, the next `flush_id` can skip numbers, so read it from the next frame. This matches our "drop audio until `Cancelled`" handling.
- `Termination` now carries `session_duration_seconds`, `total_input_char_length`, `audio_duration_seconds` and `voice_expires_at`.
- `WordBoundaries` still arrives after `FlushDone`, with zero-length entries for silent tokens ([word boundaries](https://www.assemblyai.com/docs/tts/word-boundaries.md)).
- **Documented limits:**

  | Limit | Value |
  | --- | --- |
  | `Generate` size | 2000 chars |
  | Session length | 3600 s (`3008` when reached) |
  | Idle time | 120 s (`3006`) |
  | Text intake | about 100 chars/s after a 1500-char grace |
  | Unsynthesized backlog | 8000 chars (`3010`) |
  | Control frames | 20/s, burst about 60 (`3010`) |
  | Unread audio | 300 s or 16 MiB (`3011`) |
  | Message size | 1 MiB (`1009`) |
  | New sessions | 5/min on free (`3009`) |

- New close codes to handle: `3005` `at_capacity` (retry after 2–5 s), `3008`, `3010`, `3011`, `3012` `voice_not_found`, `1012` (server restarting) ([error handling](https://www.assemblyai.com/docs/tts/error-handling.md)).
- **Billing:** per input character that reaches synthesis ([HTTP API overview](https://www.assemblyai.com/docs/tts/api-reference/http-api/overview.md#billing)).

**Markup and delivery** (`tts-markup.md`, `packages/engine/src/tags.ts`) ([prompting guide](https://www.assemblyai.com/docs/tts/prompting-guide.md))
- **Confirmed:** square, curly and angle brackets are converted to round ones and read aloud, so `[laughs]` is spoken as "laughs" and the docs say "Remove such tags". Emoji, Markdown and HTML are stripped.
- **New documented controls:**
  - `!` for emphasis.
  - `?!` for surprise.
  - Commas or ellipses for a short pause. Stacking them doesn't lengthen it, which contradicts our "ellipses add no pause" note.
  - A trailing `--` for a sudden cut-off.
  - An ALL-CAPS word for stress.
  - Inline fillers (`uh`, `um`).
  - Stutters like `c-c-can't`.
  - False starts like `That- that`.
  - Dashed digits `4-3-2-1` to read digit by digit.
- Server-side normalization covers currency, phone numbers, dates and so on.
- The model is now **AssemblyAI-TTS-1** ([models reference](https://www.assemblyai.com/llms/models.md)). The local claim that it's Kyutai Pocket TTS came from the CLI repo and may be outdated.

**Added (other interfaces):** an HTTP API (`POST https://tts.us.assemblyai.com/v1/speech`, an SSE `/v1/speech/events`), an OpenAI-compatible route, LiveKit and Pipecat plugins, and SDK `TTSSession` ([choose an interface](https://www.assemblyai.com/docs/tts/getting-started/choose-an-interface.md), [OpenAI compatibility](https://www.assemblyai.com/docs/tts/openai-compatibility.md)).

**Inconsistent:** the FAQ still says "AssemblyAI does not offer standalone text-to-speech" ([FAQ](https://www.assemblyai.com/docs/faq/do-you-offer-voice-to-voice-or-text-to-speech-tts.md)), which contradicts the new TTS section and the launch note in [models.md](https://www.assemblyai.com/llms/models.md).
